## 1. 输入包的性质（先判性质，再谈合并）

这个 zip **不是完整模块包**，是"脚本层覆盖包"：只有 `*.sh`、`libexec/*`、`webroot/index.html`、
`module.prop`、`docs/*`；**没有** `seed/`（服务端载荷）、`tools/`（curl、CA）、`zoneinfo/`、
`META-INF/`、`webroot/status.json`。它的 `customize.sh` 也不是安装器，而是"把包内文件覆盖进已安装目录
再调 `hotinstall.sh`"的补丁脚本。

所以合并策略是**取其脚本、弃其安装器**：脚本与文档逐文件合并，安装器存进 `overlay/` 作参考
（见 `overlay/README.md`），仓库的 `module/customize.sh`、`seed/`、`tools/`、`zoneinfo/`、
`META-INF/`、`webroot/status.json` 一律保留。

## 3. 与 R01–R19 的关系（重点：不能回退）

用户这版是在 magisk.32 之上继续改的，19 组修复全部保留，其中三处被**加强**而非替换：

- **R01（健康通过后才删旧载荷）**：提交点仍在"拉起并健康通过之后"，但动作抽成
  `supervise_commit_pending()`，并在 `payload_commit_old()` 里再加"锁内重读 pending + 代次校验"。
- **R03（跨代误删）**：由"tag+pid 比对"升级为"pending / 本次子进程启动代次 / 磁盘代次三方一致"，
  兼容无代次的旧 pending（回退到 tag 匹配）。
- **R04（回滚不收敛）**：`_upd_rb_ok` 判定保留，失败分支追加数据回滚与服务恢复。

新增能力（原报告没有、这版补上的）：

1. **更新事务时序**：staging → `upd_stop_service`（停服并核实退出）→ `payload_data_snapshot` →
   原子切换 → 健康校验（并用 `/proc/<pid>/exe` 确认命中的是新载荷进程）→ 提交。
   旧实现是"切换完就提交"，服务还在跑旧进程时也可能被判健康。
2. **数据快照与回滚**：`$BACKUPDIR/data-prev` + `data-prev.txid`，切换前 `cp -a` 并核验
   `*.db/-wal/-shm` 字节数；回滚用 `$DATADIR.restore.$$` → `$DATADIR.upgraded.$$` 现场保全。
   `a2a rollback --with-data` 把"旧程序 + 旧数据"一起回退，并在无开关时提示"旧程序 + 新数据"。
3. **txid 代次绑定**：`update.pending` 扩为 `tag pid path txid startticks`，另有
   `$RUNDIR/payload.generation`；提交要求三方一致，`payload.switching` 记录切换现场。
4. **`update.pending-verify`**：更新时服务本来就停着（`UPD_WAS_RUNNING!=1`），只切载荷不做健康验证，
   单独落一个"已安装未验证"标记，等下次开机/启动健康通过后再提交。
5. **cgroup 逃逸重写**：逐行解析 `/proc/self/cgroup`，v1 按 `/proc/self/mountinfo` 找控制器挂载点
   （优先 `$4=="/"`），v2 用 cgroup2 根；写完回读 `/proc/<pid>/cgroup` 校验**每个**层级都到 `/`，
   任一失败即返回非零（诚实上报，不再"改了一个就当成功"）；`--check` 只读模式。
6. **boot-worker 统一入口**：`boot-start.sh` 与 `boot-completed.sh` 都只投递，
   `boot-worker.sh` 独占 `boot.lock.d` 串行执行"等 boot_completed → boot_delay → 等网 → DNS → 解释器修正 → 复核 autostart → 幂等启动"。
7. **hot-restart 请求文件 + 单 worker**：触发只写请求标记并抢 worker 锁；在跑的 worker 每轮重读最新请求、
   动作前重读 `autostart`，不再按过期参数重复重启；收尾有 ≤3 轮有界复检防丢失窗口。
8. **卸载零删除保护**：缺 `svc_kill_all_module_procs` / `update_lock_acquire` 直接中止（零删除）；
   进更新锁后停服，正常停不掉就强化停止，仍失败则中止；确认全退出才清锁与崩溃孤儿。
9. **DNS 三态还原**：`absent` / `empty` / `file` 分别精确还原（空文件用 tmp+mv、原本不存在则 `rm -f` 并核实），
   还原后 `dns_file_same` 读回校验。
10. **安全收紧**：`wget` 回退仅在配置了 `update_pin` 时允许（否则明确拒绝并说明原因）；
    `update_sha_via_mirror=1` 时打印"镜像可同时伪造包与校验值"的 WARNING；
    `status.json` 走 `json_escape`；WebUI 全部 DOM + `textContent`。

## 4. 验证

两个套件都从仓库内复跑（源码只读，写入全部落在隔离目录）：

- `test/verify_fixes.py` —— **37 项全绿**（R01–R19 原 32 项 + 本轮新增 5 项 localfix 行为）：
  - `lf_generation_mismatch_blocks_commit`：子进程代次与 pending 不一致时**不提交**，旧载荷与 marker 全留。
  - `lf_hot_request_roundtrip`：请求写入 → 读回 → 锁释放 → 清除，无残留 tmp。
  - `lf_dns_file_same`：相同 / 不同 / 单边缺失 / 双边缺失 四种比较结果正确。
  - `lf_json_escape`：引号、反斜杠、换行、空串按规定转义。
  - `lf_boot_entry_and_wget_guard`：开机入口只投递 worker、`boot-worker.sh` 存在且带 `BOOT_LOCK`、
    wget 闸门在 wget 探测循环之前、拒绝文案存在。
- `test/verify_loop.py` —— **8 场景全绿**，并新增"拉起成功后确实走到 `supervise_commit_pending`（commits>0）"断言。
- `sh -n` 全量 21 个入口（`*.sh` + `libexec/*.sh` + `libexec/a2a` + `META-INF/.../update-binary`）全过。

测试台自身修了两处（都不是被测代码的问题）：

- `func()` 原先靠花括号配平截取函数体，遇到函数内的 `|| { ... }` 分组或 awk 的 `BEGIN { ... }`
  会**提前截断**，导致用例语法错误。改为"以第 0 列的 `}` 收尾"（本仓所有顶层函数体都这么写）。
- `r01_supervisor_commits_after_health` 在提交动作被抽成函数后，切片里只剩调用，需一并带上函数本体，
  并显式设置 `CHILD_GENERATION`（用例把 `start_child` 桩掉了）。

## 5. 仍未覆盖的

- **无真机回归**：全部在 Windows + msys `sh` 沙箱执行，msys `sh` ≠ Android BusyBox `ash`。
  安装、开机拉起、在线更新、回滚、`a2a rollback --with-data` 这条完整链仍需上机验证。
- **`cgroup_escape` 的真实效果**依赖设备 cgroup 布局与 Root 管理器实现，沙箱只能验证解析与回读逻辑。
- **数据快照的磁盘水位**：`space_require_kb` 只做估算，`data-prev` 常驻会在数据目录翻倍占用。
- **两处 R15 边角仍未闭合**：`control.sh` 的 `svc_start_impl` 在 `setsid` 前 `rm -f "$RUNDIR/stop"`
  会抹掉刚点的停止标记；`boot-worker.sh` 复核 `autostart` 但**不**复核 stop 标记与门禁。
  这两处原报告已列为"看到但未修"，这版沿用同样处理。
